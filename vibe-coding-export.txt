 PROJECT OBJECTIVE:
 Design and build a Vibe coding program using https://github.com/CKissinger1988/Velocity
 as the core AI agentic framework, integrating features and functions from
 https://github.com/Spartan-Software-Enterprises/Spartan-IDE to create the best
 cross-platform (Windows, Linux, Android) vibe coding program—focused on lightweight
 local AI models, MCP protocol integration, optional remote dev server connectivity,
 and user-created home servers, without building a full IDE.

--------------------------------------------------------------------------------
 CORE PHILOSOPHY:
 - Velocity is the core; add features/functions from Spartan-IDE
 - Result is a "vibe coding program" not a full IDE
 - Android-first priority: Android adaptation is the biggest priority
 - React Native + Expo + MLC Chat/PocketPal AI runtimes

 - Model strategy: 1.5B-4B quantized GGUF models (Phi-4-mini, Qwen3-1.7B)
 - No Ollama mandate; multiple runtimes (llama.cpp, MLC, WebLLM)
 - Multiple quantization: Q4_K_M, Q4_0, Q3_K_S

 - MCP protocol: MCP Lite (default, simplified), Full MCP (with sandboxing),
   MCP Bridge (Android/REST proxy)
 - Remote dev servers: Optional backend for future subscription service;
   user-created cloud VPS (DigitalOcean, Linode, Vultr) and home/self-hosted servers
 - SSH + platform APIs; local-first works fully offline

 - Key constraints: READ-ONLY plan mode initially; all analysis and planning only;
   preserve exact file paths and identifiers; respond in same language as conversation

 MODEL INTEGRATION RESEARCH:

 Model Runtimes & Quantization:
   - GGUF format: primary delivery format for quantized models
   - Quantization levels: Q4_K_M (quality balanced), Q4_0 (faster, slightly less quality),
     Q3_K_S (smaller, good for edge)
   - Target models: Phi-4-mini (3.8B), Qwen3-1.7B (2.1B), Llama-3.2-1B
   - Multiple runtimes: llama.cpp (primary), MLC Chat (Apple silicon accelerated),
     PocketPal AI, WebLLM (browser-based), Ollama (server-side)

 Hugging Face Hub:
   - 70% of models carry no license (research finding: May 2026)
   - Licensing distribution covers only a third of models
   - Must filter by explicit license before download
   - Model card metadata includes license identifier
   - Commercial use varies by license (Apache 2.0, MIT allow; GPL-3.0 restricts;
     RAIL-restricted has use case limitations)

 Specific Models Researched:
   - Phi-4-mini: MIT/Apache compatible, good for 1.5B-2B range
   - Qwen3-1.7B: Apache 2.0, strong performance at 1.7B
   - Llama-2-70B: Meta Community License, "Built with Llama" attribution required,
     monthly active user thresholds
   - BLOOM: RAIL license, restricts medical/legal use cases
   - Dolly 2.0: Permissive license, commercial use allowed
   - Vicuna: Derived from LLaMA, research-only restrictions apply

 Model Gateway Strategy:
   - Local first: On-device GGUF models (offline-first)
   - Edge acceleration: NPU/Vulkan when available
   - HF Hub fallback: Gemini/OpenAI APIs when local insufficient
   - Cost-aware routing: Select cheapest adequate model per task

 PROTOCOL STRATEGY:

 - MCP Lite: Default, simplified protocol, no handshake complexity
   - JSON-RPC 2.0 based
   - Android/mobile primary
   - Minimal overhead, proven adoption (Claude Code, Cursor, Cline)

 - MCP Bridge: RESTful proxy for resource-constrained environments
   - Android/REST proxy pattern
   - No STDIO complexity
   - When remote connectivity needed without full MCP stack

 - Full MCP: When needed, with sandboxing v2.1
   - Complete protocol with all primitives
   - Server discovery, tool registration
   - Production security with scopes

 - SSH/MOSH: Resilient terminal fallback
   - Survives network changes
   - Proven by Moshi implementation
   - When terminal reliability critical

 - SSE Streaming: Real-time output
   - Server-Sent Events
   - Terminal output, chat streaming
   - opencode-mobile proven pattern
